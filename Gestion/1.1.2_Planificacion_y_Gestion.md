## 1. INTRODUCCIÓN Y EQUIPO

### 1.1 Resumen Ejecutivo
Menu Bites es una solución SaaS multitenant diseñada para optimizar la operación de restaurantes medianos y grandes. El sistema integra el flujo completo desde que el cliente escanea un código QR hasta que el pago es procesado en caja, pasando por una gestión en tiempo real en la cocina (KDS) y terminales para garzones.

## 2. CONTEXTO Y PROBLEMÁTICA

### 2.1 Descripción de la Problemática
La industria gastronómica enfrenta desafíos críticos en la velocidad de atención y la precisión de los pedidos. Los errores en la comunicación entre salón y cocina, sumados a la lentitud en el proceso de pago y solicitud de cuenta, impactan negativamente en la rotación de mesas y la satisfacción del cliente.

### 2.2 Situación Inicial (As-Is)
Actualmente, muchos establecimientos dependen de comandas físicas o sistemas locales sin sincronización en tiempo real, lo que genera cuellos de botella durante las horas punta y falta de visibilidad centralizada para la administración.

---

## 3. OBJETIVOS Y ALCANCE

### 3.1 Objetivo General
Desarrollar e implementar una plataforma digital multitenant que automatice el ciclo de vida del pedido en un restaurante, garantizando sincronización en tiempo real en menos de 2 segundos entre todos los actores (Cliente, Garzón, Cocina, Caja).

### 3.2 Objetivos Específicos
*   Implementar un sistema de autenticación robusto con aislamiento de datos (Multi-tenant) mediante RLS.
*   Desarrollar un Kitchen Display System (KDS) interactivo para la gestión de tiempos de preparación.
*   Crear una interfaz de cliente web/móvil accesible vía QR para pedidos autónomos.
*   Centralizar la administración de múltiples locales en un Dashboard global.

### 3.3 Alcance Técnico
*   **Entregables:** Software (Monorepo), Manual de Usuario, Documentación Técnica (SAD), Reportes de Avance.
*   **Restricciones:** Uso de infraestructura Cloud (Supabase/Vercel) en capa gratuita. Plazo de entrega final de 16 semanas.

## 4. PROPUESTA DE SOLUCIÓN Y DISEÑO CONCEPTUAL

### 4.1 Definición de Requerimientos

#### Requerimientos Funcionales (RF)
*   **RF-01 (Autenticación):** Login seguro con roles (Admin, Cajero, Garzón, Cocina).
*   **RF-02 (Gestión Realtime):** Sincronización instantánea de pedidos mediante Supabase Realtime.
*   **RF-03 (Menú Digital):** Visualización de productos y categorías mediante escaneo QR.
*   **RF-04 (KDS Kanban):** Visualización y transición de estados de pedidos (Nuevos, Preparando, Listos).
*   **RF-05 (Cierre de Caja):** Validación de pagos y estado terminal 'COMPLETED'.

#### Requerimientos No Funcionales
*   **Seguridad:** Aislamiento total de datos entre restaurantes mediante Row Level Security (RLS).
*   **Confiabilidad:** Persistencia de estados ante fallos de conexión mediante triggers en base de datos.
*   **Escalabilidad:** Arquitectura de micro-servicios (apps independientes) en un monorepo Turborepo.

### 4.2 Arquitectura y Patrones
El sistema utiliza una arquitectura de **Monorepo** para compartir lógica de negocio y componentes de UI. Se emplea el patrón **Observer** para la reactividad en tiempo real y **Repository** para el acceso a datos mediante Prisma ORM.

## 5. DESCRIPCIÓN TÉCNICA

### 5.1 Stack Tecnológico
*   **Frontend:** Next.js 15, React 19, TailwindCSS v4.
*   **Backend:** Supabase (PostgreSQL, Realtime, Auth).
*   **Infraestructura:** Vercel (Hosting), Supabase Cloud.

### 5.2 Estrategia de Versionamiento
Se utiliza **Git** con una estrategia de ramas basada en `feature-branches`, integrando cambios hacia `develop` y finalmente a `main` para releases estables.

Se utiliza **Scrum** simplificado, con ciclos de desarrollo (Sprints) de 1 a 2 semanas y revisiones de hitos coincidiendo con las entregas académicas.
